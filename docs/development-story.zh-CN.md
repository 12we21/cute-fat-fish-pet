## 起点：一只活在网页里的桌宠

这个项目的源头不是我们写的代码，而是 **PC2005-cloud 的 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet) 0.3.0**（MIT）—— 一只「浮在 DeepSeek Harness Web UI 上的桌面宠物」：会呼吸、会偶尔转身、会随机做动作、会在屏幕上闲逛。

它整树被导入到 [`src/`](../src)，成为之后所有事情的基线。到今天，上游发布包里 **243 个文件中有 232 个在这里逐字节未改**，11 个是刻意修改的（每一个都在 [differences-from-upstream.md](differences-from-upstream.md) 里带着大小和原因列出来），**没有删掉上游任何一个文件**，另外有引擎文件是本项目自己加的。

最初的那个念头，记录在技术日志第 2 步里，是一句很朴素的话：**让她脱离 DSH 的网页，在一个普通的 Windows 桌面上跑起来，并且能当一个独立软件用。**

那两天的活儿发生在**还没有这个仓库的时候**（2026-10-06 / 10-07）。今天能拿出来的证据，是两个备份文件的名字 —— `*.bak-before-swspeed-20261006-184728`、`*.bak-before-singlemodel-20261006-190236` —— 日期就印在文件名里。它们已经不在发布树里（上游有、这份仓库没有的就只有这两个），但它们证明了：在任何人能看到这个项目之前，它已经在跑了。

## 第一关：让她走到桌面上（1.0.0，2026-10-08 04:03）

目标很直白：**一个从没听过 DSH 的人，双击一个东西就能得到这只桌宠。**

这一步做出来的东西，后来撑起了整个项目：

- **独立运行器**（`standalone/main.mjs`、`context.mjs`、`server.mjs`）—— 给上游那个原封不动的 `apply(ctx)` 喂一个最小的假 ctx，把三个 DSH 包重定向到 `standalone/shims/`。上游引擎一行不用改，就能脱离宿主跑。
- **单 HTML 控制台**（`launcher/`）—— 启动、停止、配置她，全在一个窗口里，没有命令行。
- **首次运行自动适配** —— 从注册表读显卡显存，列本机 Ollama 已有的模型，自己挑一个聊天模型和一个视觉模型，算好上下文和看屏幕频率，写成 `device-profile.json`。用户不用点任何按钮。
- **打包流水线** —— 把仓库铺成 `stage/` 树，产出绿色 zip。

验收方式是这个项目之后一直沿用的那一套：包内自检 `stage/verify.mjs`（整树指纹 + 「不许进包」清单）、`check-release` 对源码树做逐字节比对、zip 审计（**714 个条目**、每个非 ASCII 名字都带 UTF-8 标志、15 个关键文件解出来逐字节比），再在一个隔离目录里真装真卸一遍。

> 提交：`9743b8f`（这个提交发生在项目更早的那个仓库里；本仓库最早的提交是 10-08 12:23 的 `82411e7`，所以 1.0.0 的哈希是文档里留档的，不是 `git log` 里的）

## 第二关：让陌生人也能装上（NSIS 安装程序 + 1.0.0 收尾）

绿色 zip 能跑，但让用户去解压、双击 `.cmd`、答一个路径，还是太像开发者的东西。所以当天补上了 **NSIS 安装程序**：一路「下一步」、**不需要管理员权限**、带开始菜单和桌面快捷方式、卸载项写在 `HKCU` 下（`341f19b`，验收脚本与说明补记 `ab8d89d`）。

接着是 1.0.0 的收尾（`9a4e73e`）：8 条真实使用暴露出来的体验修正（自动适配补齐聊天与视觉模型、填 Key 自动切在线、视觉可单独配、问话优先回、余额查询只有配了 Key 才出现、右键菜单与控制台联动……），外加一次**隐私排雷** —— 语音日志、自检录音、缓存目录改成跟着用户自己的数据目录走，删掉遗留的 `cli-result.json`，不再发布开发草稿目录 `patched/`。

两个当天下午冒出来的问题，一个是被真实用户（其实是我们自己的主人）撞出来的：

- **升级不该装出第二份 761 MB**（`a78b3b2`）：`Function .onInit` 去读卸载登记项里的 `InstallLocation`，旧家还在就接着用。测法是故意只留卸载项、通过向导走到「选择安装位置」，看它是不是自己填回了老目录 —— 是的。
- **GitHub 会删掉资产名里的非 ASCII 字符**（`325b460`）：一个叫 `可爱大肥鱼桌宠-1.1.0-安装程序.exe` 的文件，上传后显示成 `-1.1.0-.exe`；想通过 API 改名回中文，会被用同样的方式再洗一遍。于是所有产物名统一成 ASCII：`cute-fat-fish-pet-<version>-setup.exe` / `-win-x64.zip`。

再往后是发布前必须能回答的问题 —— **「哪部分是谁的」**（`d0351a2`）：`NOTICE.md`、第三方声明里补上在线语音服务、在线模型端点和私有数据的位置，使用说明里加了一节大白话的隐私说明，上游 MIT 原文逐字节保留并随包发布，同时写了 [code-signing.zh-CN.md](code-signing.zh-CN.md)（为什么成品没有代码签名、要签得花什么代价）。

## 第三关：从「打补丁的副本」变成「能读能建的仓库」（1.1.0）

到这里为止，项目其实还是「上游 0.3.0 的树 + 一堆补丁脚本」。**一个陌生人 clone 下来，读不懂也建不出来。** 1.1.0（`82411e7`）把这件事了结了：

- **删掉 `overlay/` 和整套补丁工具**，实际发布的源码就是 `src/`，之前被补丁改过的文件以改好的样子提交。
- **重写 `build/build.mjs`**：把仓库铺成 `stage/`（`app`、`launcher`、`standalone`、`defaults`、`assets`、`verify`，再加三块外部的 `electron`、`node`、`speech`）；`build/toolchain.mjs` 负责从已安装的桌宠目录或显式参数里找这三块运行时并校验版本。
- **新增 `build/check-paths.mjs` 隐私路径门禁**：仓库和包里都不许出现本机专属的绝对路径或私有目录。它当场就抓出了语音 worker 里写死的 `node.exe` 路径和测试假数据里的真实用户名。
- **控制桥加固**：桌面侧控制口开始要求每次安装生成的 token（常数时间比较、`0600`、写不出来就一律拒绝）；`Access-Control-Allow-Origin: *` 换成来源白名单 + `Vary: Origin`；键名含 `__proto__` 的请求直接拒；独立运行器的 `/shutdown` 改成**必须 POST + token** —— 在此之前，**任何一个网页用一个 `<img src="http://127.0.0.1:.../shutdown">` 就能把她关掉**。
- 英文优先的 `README.md` + 中文版、`SECURITY.md`、`CONTRIBUTING.md`、issue 模板、以及 `docs/` 这一整套。

验收：`check-release` 逐字节、`stage/verify.mjs` 四棵树指纹 + 25 个文件、`check-paths`（170 个文件干净）、zip 审计、以及真机静默装/卸一轮 —— **装出 711 个文件，其中 710 个与 `stage/` 逐字节一致**，数据根未动，卸载干净。

然后，**2026-10-08 12:31 / 12:34 UTC，仓库公开，Release v1.1.0 上线**（两个成品 + 两个 `.sha256`）。这是这只桌宠第一次被不认识的人拿到。

## 第四关：四个真实使用会撞上的坑（1.1.1 → 1.1.4）

公开之后的节奏变成：**被真实使用撞出问题 → 找到根因 → 修掉 → 补验收 → 发版。** 四个版本，四个坑，每一个根因都不是「表象上看起来的那个」。

### 1.1.1 —— 「双击了，窗口闪一下就没了」（`9633b0c`）

- **KI-1**：双击装到一半发现 `install.ps1` 不在（典型场景：在压缩包预览里直接双击），Windows PowerShell 打印一条错误然后**退出码 0** —— 老包装脚本的 `if errorlevel 1` 永远不触发，窗口默默消失，一句人话都没有。
- **KI-2**：便携安装器还把旧产品名和 `1.0.0` 写进快捷方式和卸载项。
- **KI-3**：UTF-8 的 `.cmd` 里放中文 + `chcp 65001`，会让 `cmd.exe` 把后面几行解析错（`'onPolicy' is not recognized …`）。
- **KI-5**（修这个版本时新发现的）：卸载器**在自己正在删的目录里运行** —— `cmd.exe` 的当前目录就是安装目录，它正在读的 `卸载.cmd` 也在里面 —— 于是那句 `Remove-Item -Recurse -Force -ErrorAction SilentlyContinue` 整体失败、静默失败，**714 个文件一个没删**。

改法很笨但很对：`.cmd` 全部改成纯 ASCII、无 BOM、LF，先检查自己需要的文件在不在，中文提示改用 `powershell -EncodedCommand` 输出（与代码页无关），永远 `pause`；卸载脚本先把工作目录停在 `%TEMP%`，再把删不掉的残渣交给一个隐藏的 PowerShell 助手，等窗口关掉后重试最长约两分钟。

验收是真跑一遍发布出去的 zip：解压 714 个条目 → `安装.cmd` 10.2 秒 → 逐字节比对 **710/710 一致（797,834,384 B）** → 卸载，**安装目录在窗口关闭后两秒内消失**。

### 1.1.2 —— 「她把思考过程整段念出来了」（`dba4e2d`）

两个根因，一个比一个隐蔽：

- 存下来的 `online.json` 里模型名写成了 `DeepSeek-chat`，而那个端点提供的是 `deepseek-flash` / `deepseek-v4-pro`；**首字母大写的名字会返回 HTTP 400** —— 也就是说，那条在线路径其实一直是不可用的。
- 更要命的是**思考型模型**：桌宠的预算是 20–40 个字，实测结果是 **`content` 0 个字、`reasoning_content` 556 个字**，而 `online.mjs` 退而把 reasoning 当台词念了出来。`"enable_thinking": false` 不是真开关（仍有 21 token 在思考）；`"thinking": {"type": "disabled"}` 才是。

修完的效果：同一句话从 **400 token 的思考变成 2 token**，并且策略改成「只想了、没写正文」就**如实报错，绝不念思考**；顺手修掉「字符串形状的消息被静默变成空 prompt」。

### 1.1.3 —— 「打开 A站首页」没反应（`bd0ebd1`）

原话是：语音模式下她要能听懂并执行「打开xx游戏 / 打开A站首页 / 打开XX文件夹」——软件、网址、文件夹三种都算。

侦察结果：语音和打字走的是**同一个函数**，而它只有两个桶 —— `isUrl(…) ? 'url' : 'app'`，`isUrl` 只认 `^https?://`、`www.` 和一张很短的后缀表；主进程那边也**完全没有**「本地文件夹/文件」的分支。所以「打开 A站首页」「打开 下载文件夹」「打开 报告.docx」全都过不了解析。

改法是新增一个纯逻辑文件 `targets.js`（网址 → 本机路径 → 盘符 → 系统文件夹 → 站点别名 → 软件兜底），`sprite.js` 加语气词归一与「搜一下/百度一下」，`main.js` 加 `kind:'file'` 的 `openLocalTarget()` —— **只读、只开、跳过 `.lnk/.exe` 这类软件**（文件权限绝不能变成偷偷启动软件的通道），重名只问不做，并且它单独配了一个默认关闭的权限开关。

验收：离线 **72/72**、真 Electron 渲染端 CDP **21/21**（含真主进程打开下载文件夹），包内自检还抓出它自己一个「假阴性」。

### 1.1.4 —— 「我只需要能主动隐藏 API key 的功能」（`d30a214`）

起因是主人要录宣传视频，说控制台里的敏感东西、尤其是 API Key，会被拍进去。她的第二句话当天就把范围钉死了：

> 「我只需要能主动隐藏 API key 的功能，不要加录制什么的」

于是：两个 Key 输入框改成默认显示圆点、各配一个「显示 / 隐藏」按钮由她自己决定什么时候看；写入终端前按三种形状脱敏（已保存的整串、`sk-…`、`Bearer …`），**其余文字一个字都不改**（连 `C:\Users\…` 这种普通路径都原样通过）。

第一版顺手加的「录制模式」总开关，**当天按她的要求整条删掉**，页面里没有留下任何痕迹。验收 26/26：两个框初值是圆点而 `.value` 是真 Key、显示按钮只影响那一个框、页面里不存在 `#privacyMode` / `#privacyBadge` / `body.privacy` / localStorage 键、屏幕上任何位置都搜不到明文 Key。

## 第五关：让她自己升级（1.2.0）

公开版本到了 1.1.4，升级路径还是：自己去 GitHub 下 348 MB，然后在一个正在运行的桌宠上手动装。1.2.0（`1f7fbdd`）把这件事变成控制台里的一个按钮。

设计被两个事实逼出来：

1. **运行中的 `electron.exe` 不能覆盖自己的文件** —— 所以安装必须发生在控制台退出**之后**。
2. 从 Electron 主进程用 `DETACHED_PROCESS` 起一个 PowerShell **不可靠**：在这个环境里它立刻返回退出码 0，什么都没干 —— 这正是第一版在真机上静默失效的原因（**KI-10**）。

于是有了那套交接：控制台问一次 GitHub 的 `releases/latest` → 有新版就显示 `当前 X → 新版 Y` → 点「下载并更新」流式下载（边下边核对 sha256，短读、哈希不符、**没有 digest 一律不装**，下过的完整包直接复用）→ 窗口自己关掉 → 现场生成的 `apply-update.vbs` 拉起 `apply-update.ps1`（VBS 存在的唯一理由就是：PowerShell 是控制台程序，没有控制台时它会立刻退出）→ 等控制台 PID 退出 → 停掉桌宠 → 静默装 `/S /D=<安装目录>` → 删掉安装包和四个便携脚本 → 写 `last-result.txt` → 把控制台开回来 → 下次启动如实回读「刚更新过」或「上次更新没成」。

写这套东西的过程留下三个 KI：**KI-9**（流式下载其实从没写进磁盘，而哈希之所以「对」是因为哈希和文件被喂了同一批 chunk）、**KI-10**（上面那个交接）、**KI-11**（用 `+` 而不是 `,` 拼 PowerShell 数组，静默地只得到一个文件名）。

验收：离线 **97/97**、真机端到端 CDP **21/21** + 回读 **4/4**、更新后那棵树 **712 个文件逐字节一致**、`failures: 0`。

## 三处「先就地补上，等下次发版」

1.2.0 发布后，同一天里主人又连续报了三件事。她的指示是同一句：

> 「只是修复，不用发 1.2.1，沿用 1.2.0」

所以这三处都没升版本号、没重打包、没发新 release，只提交到 `main`，并且**把她那台机器上的文件就地换成修好的版本**，让她当场就能用：

1. **「测一下通不通」点完什么都没发生**（`1054b79`）：结果只写进页面最下面的终端，而用户停在顶部；而且探测读的是**已保存**的配置，填了新 Key 直接点测的还是旧配置。改法是每颗按钮下面多一行当场变色的状态（琥珀「正在问……（最多 20 秒）」→ 绿「通了（N ms），它回「…」」/ 红「没通 —— 原因」），点下去先把框里的值存下来再测。验收 32/32。
2. **控制台互动性审一遍**（`41b317b`）：她说的是「模拟真人，对UI设计界面的互动性进行分析，不好的进行优化」。新写的 `ui-audit.cjs` 用 CDP 真的悬停、真的按 Tab 走完 40 个停靠点，量出四类毛病：全站只有 2 条 `:focus` 规则（Tab 看不见焦点在哪，「在线 / 本地 / 自动择优」还是 `display:none`，键盘根本进不去）；折叠栏的 `<summary>` 只有 19px 高，看起来 52px 都能点其实上下边缘没反应；终端在 y=1834、只有 104px 高，而大多数动作的结果只写进终端；改了值没有任何「有改动没保存」提示。改完 15/15，页面高 2405 → 2375px。
3. **问她「在线还是离线」，她说「离线模式」，但控制台显示在线**（`465112d`）：先证明**切换其实是成功的** —— 轮询她正在跑的桌宠的 TCP 连接，抓到了连续 6 次 `Established …:443`（`api.deepseek.com`）和 944ms 的回答。真正的原因是：**从来没有任何机制告诉模型它现在是哪一档、用的哪个模型**，人设 prompt 里只有「温柔乖巧、叫主人」，它自己猜了个「离线」。修法是在 `src/lib/index.js` 里新增一段**由代码如实回答**的逻辑（读 `screen-watch/state.json` 的 brain），并且让「问句 + 档位词」先于切换口令被识别 —— 以前「你现在是本地模型吗」会被当成切换命令**把档位真的改掉**。

## 最后一步：让所有人都拿到最新（1.2.1）

主人先问了一句：

> 「我现在桌面上的那个可爱大肥鱼桌宠就是最新版了是吗？」

核对结果是：**她那台机器上的确实是 `main` 的最新代码**（1.2.0 + 上面三处就地补丁，712 个文件与 `stage/` 逐字节一致），但**版本号仍显示 1.2.0**，而 GitHub 上发布的 1.2.0 成品还是旧行为 —— 别人下载到的并不是最新。

然后她说：

## 名字

2026-10-10，产品名统一成了 **蓝毛小女仆（Blue-Haired Little Maid）**，而仓库、npm 包、安装器仍然沿用旧名 **Cute Fat Fish Pet /「可爱大肥鱼桌宠」**。

这不是犹豫，是**故意**的：看得见的地方改名，看不见的地方一个都不动。`BlueHairMaid`（安装目录、卸载项）、`dsh-pet`（插件包名）、`dsh-pet-electron-helper`、`/dsh-pet-7340`（本地路由前缀）、`%APPDATA%\BlueHairMaid`（数据目录）—— 改任何一个，老用户的设置、人设、记忆、快捷方式和「应用和功能」里的那一条就全对不上了，会变成「第二只桌宠」。

一句话：**改看得见的，永远别碰看不见的。** 这正是从 1.0.0 升上来对用户来说是个 no-op 的原因。

## 这一路一直没变的三件事

**一、每个数字都要能被别人自己核对。** 这个项目从 1.0.0 起就有一个习惯：不写「已验证」，写「怎么验的、验出多少」。所以有了 `check-release`（`stage/` 必须与仓库逐字节一致）、`verify.mjs`（整树指纹 + 关键文件）、`check-paths`（隐私路径）、`verify-install.py`（装出来的树逐字节比对）、以及 one-off 的 CDP 验收脚本（97/97、72/72、32/32、26/26、21/21、18/18+4/4）。发布说明里的每个哈希，都能用 `certutil` / `Get-FileHash` 对上。

**二、隐私是在写代码时就挡住的。** 不是事后声明，而是门禁：`check-paths` 在打包第 0 步跑，过不了就别想打包；它自己也抓过。离线语音随包走、看屏幕是可关的、API Key 默认圆点、写终端前脱敏、本机端口只绑 `127.0.0.1`、控制口要 token。

**三、她自己决定。** 打开文件夹/文件单独一个默认关闭的权限开关；要不要看 Key 由她点；要不要发版由她说 —— 「只是修复，不用发 1.2.1」就真的不发，「那肯定要让别人用到最新的」就当晚发。产品里所有替用户做主的地方，最后都改成了「问一句」。
