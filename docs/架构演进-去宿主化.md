# 架构演进：去宿主化

> 这份文件是**计划**，不含任何代码改动。目标：把 `src\lib\index.js` 里那种「插件式」写法
> （每次用到才去解析、拿 `ctx` 上的服务、把状态藏在装配闭包里）一步步改成更直接的内部调用，
> 让桌宠本体的默认活法就是「独立进程里的一个普通模块」，而不是「寄生在宿主里的插件」。
>
> 适用版本：1.1.0。行号均指本仓库当前文件，重构时会漂移，以函数名/关键字为准检索。

## 1. 现状：一份源码，两种活法

```
                     ┌──────────────────────────────────────────┐
   宿主半侧 (host)   │  src\lib\index.js   2969 行 / 113465 B    │
                     │  name="pet"  inject=[...]  apply(ctx)    │
                     └───────────────┬──────────────────────────┘
                                     │ 同一份 apply(ctx)
        ┌────────────────────────────┴────────────────────────────┐
        │                                                         │
   ┌────▼─────────────────────┐                    ┌──────────────▼─────────────┐
   │ ① DSH 宿主（插件形态）    │                    │ ② 独立版（standalone\）     │
   │  DSH 提供真 ctx：         │                    │  伪 ctx（context.mjs）      │
   │  webServer/llm/credentials│                    │  + 真 http 服务（server.mjs）│
   │  /commands/session 事件   │                    │  + 三个包替身（shims\）      │
   │  浏览器半侧由 DSH 装载    │                    │  桌面渲染端自带 renderer     │
   └──────────────────────────┘                    └────────────────────────────┘
```

关键事实（都已核对）：

- **插件三件套**：`src\lib\index.js:1496 const name = "pet";`、`:1497 const inject = ["webServer","agentDefaultModel","credentials","llm","commands"];`、`:2969 export { apply, inject, name };`
  挂载声明在 `src\cordis.patch.yml`（`insert: [{ id: pet, name: 'dsh-pet' }]`），由 `src\package.json:86-96` 的 `dsh.bundle.patch` 声明。
- **独立版怎么跑起来的**：`standalone\main.mjs:69-73` 用 `ALIASES` 把三个宿主包指向替身，`:75-84` 用 `registerHooks({ resolve })` 在**运行期**做 alias（上游是构建期 alias，我们没有构建链）；`:32 DEFAULT_APP_DIR = resolve(HERE, "..", "app")`；`:508` 特意「先监听、后 apply」（插件在 `apply` 里就要读 `ctx.webServer.port`）；`:574` 再动态 `import()` 宿主入口并调用 `apply(ctx)`。
- **`standalone\` 已经证明核心是宿主无关的**：伪 ctx 只实现了插件真正用到的那点表面，插件照样完整跑起来。
- **桌面桌宠其实早就和 DSH 无关**：`src\runtime\electron-helper\main.js:504` 用 `loadFile('index.html')` 装载**自己的**渲染端（`index.html:169-173` 引入 `shared-core.js / constants.js / sprite.js / events.js / renderer.js`），它不加载 `lib/client.js`。`lib/client.js`（浏览器半侧，4066 行）只服务「在 DSH 网页里出现的那只宠物」。

### 2.3 「插件式」写法本身

```js
// src\lib\index.js:1799-1808  —— 当前实现
/** 当前交互桌宠 id：/pet 已选且仍存在 → 该宠物；未选/已失效 → 有效宠物列表第一只（进程内，重启回默认） */
const resolveActivePetId = () => {
	try {
		const eff = effectivePetList();
		if (eff.length === 0) return "";
		if (activePetId && eff.some((p) => String(p.id) === activePetId)) return activePetId;
		return String(eff[0].id);
	} catch {
		return activePetId;
	}
};
```

调用点：`2183`（通知）、`2603`（`/say` 的默认宠物）、`2882`、`2920`（两个命令）。特征：

1. **状态藏在装配闭包里**：`activePetId` 是 `apply()` 作用域内的可变变量，外部无法注入、无法在测试里换掉；
2. **每次调用都重新解析**：读配置（`effectivePetList()`）→ 校验 → 回退，失败还会 `catch` 吞掉，
   于是「同一时刻不同调用点的答案可能不同」，且失败静默返回上一个值；
3. **调用点散在 4 个互不相关的功能里**（通知、路由、命令），谁都不是「宠物注册表」的主人；
4. 同类写法在文件里还有一批（`helper` / `startRetryTimer` / `electronEnsure` / `disposed` / `hasDesktopPet` / `broadcastCache` 等装配级可变状态，见 `1814`、`1835-1840`、`1791-1797`）。

## 3. 目标架构：core / adapter / host 三层

```
src\lib\index.js            ← 最终只剩一个薄适配器：把 DSH 的 ctx 翻译成 core 的 options
src\lib\client.js           ← 浏览器半侧：不再自己拼 URL，base 由宿主传入
        ▲                                    ▲
        │                                    │
┌───────┴─────────────────┐      ┌───────────┴──────────────┐
│ host\adapters\dsh.ts    │      │ host\adapters\standalone │  ← 现在 standalone\ 里那套「伪 ctx」升级
│ ctx → { log, register,  │      │ { log, register, llm,    │
│         llm, events }    │      │   events, balance }      │
└───────┬─────────────────┘      └───────────┬──────────────┘
        │                                    │
        └──────────►┌────────────────────────┴───────────────┐
                    │ host\core\   （宿主无关的桌宠本体）      │
                    │ PetRegistry / Router / Chat / Watch /  │
                    │ Audio / Automation / Storage            │
                    └────────────────────────────────────────┘
```

- **core**：只认自己定义的接口（`Logger`、`RouteRegistrar`、`Llm`、`EventSource`、`Balance`、`Paths`），不认 `ctx`；
  所有状态由 `createPetCore(options)` 一次性构建并返回句柄（句柄里含受控的 `registry`、`dispose()`）。
- **adapter**：每个宿主一个薄文件，做「翻译」和「补口子」，**不含业务逻辑**（现在 `standalone\context.mjs` 里那段
  「两路模型降级」「余额直查 DeepSeek」应该从 `ctx` 挪进 core 或独立服务，而不是继续挂在 ctx 上）。
- **host**：DSH 插件形态（保留兼容，可选）、独立版（默认）。两者都只做「起 adapter、调 core、注册路由」。

## 4. 分阶段计划

> 原则：**先加适配层，再切默认，最后才删旧路**。每一步都能单独回滚，且每一步结束时产品行为不变。

### P0 · 立契约，不动行为

- 给 core 定接口（TypeScript 类型 + 一页说明），把 `standalone\context.mjs` 的伪 ctx 当作**第一个 adapter** 的参考实现。
- 把三个 shim 的语义写成测试（`resolveDshHome` 与 `dshHomeDir` 逐字一致；`credentialRef` 恒等；`BlockAssembler` 的 `blocks()` 形状）。
- 产出：接口清单 + 依赖表（谁读谁的什么），落成文档，不改代码。

**验收**：`npm test`（`src\src\host\*.test.ts` 等 9 个 host 测试 + shared 测试）全绿；`standalone\check.mjs` 全 OK。

### P1 · 消灭 `resolveActivePetId` 这类「延迟解析」

- 建 `PetRegistry`：构造时读一次配置，暴露 `list()`、`byId(id)`、`active()`、`setActive(id)`、`subscribe(fn)`；
  「id 失效就回退第一只」这条规则**只写一次**，放在 `active()` 里。
- 4 个调用点（`2183`、`2603`、`2882`、`2920`）改成 `pets.active()`；`activePetId` 从闭包变量变成 registry 内部状态，可注入、可单测。
- 同类处理：把 `hasDesktopPet` / `refreshDesktop()`（`1814-1823`）并进 registry 的派生视图，避免「两处各自算一遍」。

**验收**：新增 `pet-registry.test.ts`（空列表、当前 id 失效、显式指定 id、配置抛错四个用例）；命令文案与 `/say` 行为逐条对齐旧行为。

### P2 · 路由前缀与资源 URL 注入化

- host 侧：`ROUTE_PREFIX`（`1509`）与 `2857` 一带的 `configUrl` 改成由 adapter 传入的 `options.routePrefix`（独立版保留 `/dsh-pet-7340` 以免破坏老数据，DSH 侧可换）。
- client 侧：`lib\client.js` 里那 20 余处硬编码前缀统一走一个 `routes` 对象（已有 `opts.baseUrl` 的函数就接上它），
  CSS 里的 `url("/dsh-pet-7340/…")`（`464`、`2680-2681`）改成注入的 CSS 变量。
- 目标：**换前缀只改一处**，且桌面渲染端与浏览器半侧共用同一张路由表。

**验收**：独立版截图/动画/表情/气泡/设置面板六条路径全部正常（`standalone\check.mjs` 的 `/config/meta` 存储项检查 + 手工点一遍控制台）。

### P3 · 三个宿主包去依赖

- 把 `@deepseek-ai/dsh-home-paths`、`-credentials`、`-llm` 的**本体实现**放进 `src\src\host\platform\`（内容就是现在 shim 的等价实现，`blockassembler` 等保持同一形状）。
- `src\lib\index.js:6-8` 改成从 `platform\` 导入；DSH 适配器里再用真包覆盖（或保持原样优先）。
- `src\package.json` 的 `peerDependencies` **暂不删除**（DSH 插件形态还要用），只在文档里标注「独立版不再需要」。

**验收**：`standalone\` 里删掉 `registerHooks` 也能跑（这条作为 P3 的标志性成果）；DSH 插件形态回归通过。

### P4 · 浏览器半侧与 UI 槽位解耦

- `lib\client.js` 的 `inject = ["slots", …, "connection"]`（`3986`）与两处 `ctx.slots.inject`（`4027`、`4040`）
  改为「优先用宿主槽位，没有就挂到自己创建的挂载点」——桌面模式已经有自渲染端，浏览器侧只差一个 fallback 容器。
- `settings.section` 这类 DSH 专有 UI 在无宿主时降级为控制台里的对应面板（控制台本来就是单 HTML，独立可用）。

**验收**：不装 DSH 也能在普通浏览器里打开桌宠页面（把 `standalone\server.mjs` 的路由挂到一个静态页上即可验证）。

### P5 · 收尾

- 默认活法切成独立版；DSH 插件形态作为**可选适配器**保留（`inject`/`name`/`export` 三件套不删，`dsh` 字段不删）。
- 删除 `standalone\shims\` 的别名机制（`main.mjs:69-84`），`lib\index.js` 不再需要运行期 alias。
- 更新 `src\README.md`（现在那份是上游说明文档，顶部已标注）与本文档的「已完成」章节。

## 5. 边界与风险

**明确不做的事**（做下去会搬走用户配置或破坏署名）：

- 不改 `src\package.json` 的 `name` / `main` / `exports` / `dsh` / `peerDependencies` 的**键名**；
- 不改包名 `dsh-pet`、`dsh-pet-electron-helper`、APP_ID / 数据目录 `BlueHairMaid`、localStorage `dsh-pet-*`、
  路由前缀 `/dsh-pet-7340`、数据根 `%APPDATA%\BlueHairMaid`（见 [NOTICE](../NOTICE.md) 第 5 节）；
- 不动上游 MIT 署名与 `assets\LICENSE.txt`；
- 不在同一版里既重构又改行为。

**风险点**：

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| `ctx.llm.stream` 契约 | 必须是 **AsyncIterable**，写成 `async` 函数会立刻 TypeError，且 rejected promise 无人接管会以 unhandled rejection 终止进程 | `context.mjs:15-20` 的两条硬教训写进适配层文档与测试 |
| `resolveModelInfo` 契约 | 必须返回 Promise（同步返回 undefined 会让调用方 `.then()` 炸） | 同上 |
| 工作状态 | 插件靠 `ctx.on("session/event")` 驱动；独立版目前是 noop（工作状态永远空闲） | P1 之后把「工作状态源」也做成注入接口，独立版可用本机端口/文件事件替代 |
| 构建链 | 现在**没有** tsdown 构建链（`src\lib\` 是签入的产物） | 改 TS 源码后必须重新生成 `lib\`；P0 要先确认这一步由谁做、怎么验证 |
| 版本漂移 | 上游 0.3.6 已有 `src/standalone/`（本仓库的独立版是从它演化来的） | 去宿主化后与上游差异变大，**不再跟随上游**，只保留 MIT 署名 |

### 6.1 事件驱动（EDA，参考 U.E.P-s-Core）

**现状锚点**

- 宿主半侧全部逻辑在 `src\lib\index.js` 一个文件里：2969 行 / 113465 B，`#region` 从 `:14`（balance）排到 `:1495`（host index）共 11 段。
- 屏幕监测不是事件驱动，而是**定时轮询 + 时间戳节流**：`src\lib\index.js:2304-2313` 在 `ctx.effect` 里 `setInterval(5000)`，`:2308` 用 `SW_RT.lastTick` 与 `intervalSec || 12` 秒比较后才 `swRun()`。
- 抓屏与消费粘在一条链上：`src\lib\index.js:1966`（`SW_DIR`）、`:1972`（`SW_EXE` = SwCapture.exe）、`:2028`（原生抓屏工具是否存在）、`:2238`（「省下一次 SwCapture」的注释）——「画面变了没有」由这条链自己判断，没有任何信号发出来。
- 两侧对齐靠拉：`src\lib\index.js:2318 handlePetRoute` 被 webServer 与桌面 bridge 各自消费，谁需要状态谁来拉。

**想改成什么**：进程内加一个轻量事件总线（`emit/subscribe/dispose`，不引第三方）。
屏幕监测只发布 `screen:changed`（附帧摘要 + 时间戳）；碎碎念与对话订阅 `screen:changed` / `pet:user-said`；动画播放订阅 `pet:action` / `pet:mood`；控制台订阅 `state:changed` 取代轮询。
现有 `ctx.on("session/event")`（`src\lib\index.js:2772`、`:2831`、`:2838`、`:2846`）降级为**适配层**：宿主事件进总线，核心只认总线。

**为什么值得**：屏幕监测与 AI 对话可以各自开关、各自替换；轮询改订阅后待机开销和「改配置要等下一个 tick」的手感一起变好；一个 2969 行的文件想拆模块，先要有一个比函数调用更松的耦合面。

**风险 / 代价**：事件顺序与重入是新 bug 源（必须定「同步派发 + 订阅里禁止再发同类事件」，否则画面变化 → 视觉 → 又发事件 → 打转）；总线必须支持 `dispose`，否则独立版反复起停会漏订阅（现在靠 `ctx.effect` 的清理语义，见 `:2304`、`:2756`、`:2771`、`:2830` 等 9 处）；与 P1 的 PetRegistry 有重叠，得等「状态主人」定下来再上总线。

**怎么验收**：关掉对话功能，屏幕监测仍按 `intervalSec` 工作且 CPU 不高于今天；反之亦然。`standalone` 连续 start/stop 20 次，订阅数不增长。

**建议阶段**：**2.0**（1.2 只做「事件名常量化 + 一处试点」，不铺开）

### 6.2 提案-治理（参考 PacaPet）：LLM 只提建议，确定性模块放行

**现状锚点**

- 模型今天能**直接**调工具：`launcher\agent.js:43-129` 是 `TOOLS` 表（`open_app:102-107`、`open_file:108-113`、`open_url:114-119`、`record:74-84`…），决定之后直接 `def.run(args)`（`:443`）。
- 唯一的把关是**权限门**：`launcher\agent.js:435` `if (def.perm && !ctx.perm[def.perm])` → 回 `permission-denied`（`:436-440`）；权限状态读不到时只写一句提示（`:368`）。
- 防绕圈靠启发式：`:429-431` 同一调用重复两次就放弃、`:460-464` `ONE_SHOT` 一次性动作办完即收尾、`:257` 把权限状态拼进提示词让模型「自己知道」。

**想改成什么**：执行拆三段——模型只产出**结构化提案**（`{intent, args, reason, confidence}`）→ **治理模块**用确定性规则校验（读同一份权限状态；路径白名单；同意图 60 秒去重；单次会话动作上限；危险动词黑名单）→ 通过才执行，拒绝时给人话理由。提案与结果各记一条审计（今天只有 `appendPermLog`，`:448`）。

**为什么值得**：现在只要权限开着，模型说开什么就开什么，治理是事后日志不是事前校验；规则是纯函数，能单测、能解释；对将来更小的本地模型是必要的安全边界。

**风险 / 代价**：多一层会带来「明明能做却被拦」的挫败感，规则必须保守起步；提案格式变化要与小模型重新调提示词（现存「兜底解析」路径 `:425-427` 要一起改）；审计别写进用户隐私（路径只留 basename）。

**怎么验收**：治理规则单测四类拒绝（权限关、路径越界、重复提案、超频）且文案可读；端到端构造「模型硬要开」的场景，权限关时必须不执行。

**建议阶段**：**2.0**（1.2 可先落「提案结构 + 审计」，执行仍走老路，用来收集真实提案分布）

### 6.3 插件化 / 模块化（参考 DyberPet、OpenPets）：`PetCharacter` 接口

**现状锚点**

- 宠物在代码里是**松散字典**：`src\src\host\config.ts:411` `export function flattenPetList(merged: Record<string, Record<string, unknown>>): Record<string, unknown>[]`；`src\src\host\index.ts:425` `const effectivePetList = () => flattenPetList(readAllConfig(configPaths));`；`src\src\shared\config.ts:16` `isDesktopVisible = (display) => display === 'desktop' || display === 'both'`。
- 条目形状是运行时约定、没有校验：`src\lib\index.js:2345` 的错误文案写着 `{pets:[{name?,id,size,balanceEnabled,display,position:{corner,marginX,marginY}}]}`。
- 「角色」与「能力」混在一起：动画在 `src\runtime\electron-helper\sprite.js:137/139`（两个 `<video>` 双缓冲）按名字播 webm、`:423` 起播；语音在 helper 内（`sprite.js:3370` 静音 tick）；屏幕监测在宿主半侧（`src\lib\index.js:1966` 起）。换一个角色要同时动三处。
- 上游的 pet pack 只是**素材层**约定（见 `src\README.md`），没有代码级接口。

**想改成什么**：定义 `PetCharacter`（id / 名字 / 人设 / 尺寸 / 素材目录 / 初始状态）与 `PetAbility`（动画、TTS、屏幕监测、动手工具）两个接口；`miko`（蓝毛小女仆）只是内置实现之一；角色可从目录导入（`defaults\` 与用户数据根各扫一遍）。能力由 `abilities: string[]` 声明并按声明装配——「关掉屏幕监测」= 不装配，而不是散落的 if。

**为什么值得**：现在的「多只宠物」其实是同一只的多份配置；接口化后才谈得上真多角色；能力可裁剪 = 待机开销可裁剪（与 6.5 相乘）；新人加角色不必读 2969 行。

**风险 / 代价**：接口定早了以后加能力要改版本，初期只定最小字段；素材目录是老约定（`assets/webm` 按中文名索引），导入新角色要允许「没有素材」的降级。

**怎么验收**：内置 `miko` 走完接口路径后，同一个 `main-config.json` 读出来的行为与今天逐条一致；复制一份角色目录改 id/名字，不改代码就能出现第二只。

**建议阶段**：**2.0**（1.2 只做「配置读成带类型的对象」这一步）

### 6.4 长期记忆（参考 pet-mochi / dot）：SQLite + FTS5 或向量库

**现状锚点**

- 记忆就是一个 JSON 全量读写：`src\lib\index.js:1649` `const memoryPath = join(userRoot, "memory.json");`；`:1652-1671` `readMemory()`（全量 `readFile` + `JSON.parse`，损坏则备份 `.bak-<ts>` 再从头开始）；`:1672-1675` `writeMemory()`（全量覆写）；`:1677-1681` `withMemoryLock()` 只用一条 Promise 链串行化；`:1693-1697` `memoryRounds()` 决定记几轮（默认 5）。
- 也就是说今天的「记忆」= 最近 N 轮问答 + 人设字符串（`petSystemPrompt()`，`:1684-1691` 取 `whisperPrompt` 加一句名字声明）：**没有搜索、没有分层、没有过期**。

**想改成什么**：本地库（SQLite + FTS5 最省事，或轻量向量索引）分三层——`episodic`（原始轮次）、`semantic`（提炼出的关于主人的事实/偏好）、`persona`（人设与关系）；对外只暴露 `remember()` / `recall(query, k)` / `forget(id|query)` / `exportAll()` / `wipe()`。库打不开时回退 `memory.json`，绝不因为存储层坏了就开不了口。

**为什么值得**：「可读、可删、分层」是用户信任记忆功能的前提（今天只能翻一个越来越大的 JSON，删只能整删）；检索式召回比「最近 5 轮」省 token，也不会出现「上周说过的事完全不记得」。

**风险 / 代价**：要引依赖（`node:sqlite` 在 Electron 里版本受限，第三方库要过许可与体积）；老 `memory.json` 要一次性导入并保留原文件（用户可能手改过）；库里会有主人原话，必须落在数据根、跟随现有「卸载时可一起删」的流程。

**怎么验收**：迁移测试（老文件 → 库，召回包含原有轮次；库损坏自动回退且不丢原文件）；`forget` / `wipe` 单测；控制台能看到「她记住了什么」的只读列表。

**建议阶段**：**2.0**（1.2 只加「记忆导出 / 清空」的可视入口，不动存储格式）

### 6.5 性能：待机 CPU

**现状锚点**

- **桌面端是软件合成**：`src\runtime\electron-helper\main.js:114-121`，因为 Windows 分层窗口在 DWM 下的两个已知缺陷，win32 上直接 `app.disableHardwareAcceleration()` —— 动画全靠 CPU 合成。
- 动画本体是双 `<video>` 播 VP9-alpha webm（`src\runtime\electron-helper\sprite.js:137/139`，起播 `:423`）；位移 / 拖拽 / 抛掷 / 压缩是四个 rAF 循环（`:682/688`、`:894/896`、`:986/988`、`:1015/1023`）。
- 常驻轮询：指针 **60 ms** 一次（`main.js:315 const POINTER_POLL_MS = 60;`，循环 `:487-495`，每次都 `getBounds()` + `screen.getCursorScreenPoint()`，必要时 `setWindowIgnore`）；宿主存活探测 `main.js:109-111`；屏幕监测 5 s tick（`src\lib\index.js:2305-2311`）；语音静音 tick 10 s（`sprite.js:3370`）。
- 「GPU 查询」不是热路径：显存只在首次运行读一次注册表（`standalone\detect.mjs:44-45`）；贵的是上面那两行。

**想改成什么**：三层节流——① 待机时降帧率 / 降 `playbackRate`，不可见时暂停 video（`:423` 一带）；② 完全暂停不活跃模块（屏幕监测在无人互动时停 tick，指针轮询在鼠标不动时退避到 200~500 ms）；③ 抓屏只在需要时用原生 SwCapture（`src\lib\index.js:2028`，单次 90~180 ms，已是优化后的路径）。若将来能回到硬件加速，`main.js:114-121` 是第一优先。

**为什么值得**：桌宠是常驻程序，待机 CPU 直接决定用户会不会在任务管理器里把它关掉；屏幕监测的视觉调用按 12 秒节流（`src\lib\index.js:2308`）是待机最大的单笔开销。

**风险 / 代价**：降帧可能让「待机呼吸」看起来卡，应该给用户「动画质量」开关而不是替他决定；指针退避影响「看向光标」的手感（`:482-485` 已有「没动就不发 IPC」，可在此基础上自适应）；软件合成是**为修 UI bug 故意选的**，动它先要复现那两个缺陷（拖拽黑边、大透明窗盖小窗内容丢失）。

**怎么验收**：固定场景（待机 10 分钟、无鼠标输入）先记一份今天的 CPU 基线，改后要低于它；不活跃模块暂停后，鼠标一动 / 说一句话必须在 1 帧内恢复；回归上面两个分层窗口缺陷。

**建议阶段**：**1.2**（小步：指针退避、待机降帧、监测停 tick 三件事，各自独立开关、各自可回滚）

### 6.8 为什么这一版（1.1.0）刻意不做大重构

- **1.0.0 的行为是主人已经验收过的**：结构重构必须每一步都配独立验收（「行为逐条对齐」的证词），不能和「独立仓库 + 安全 + 隐私」这一版混在一起发布 —— 混在一起出问题，没法二分定位是结构改坏了还是打包改坏了。
- 这一版的验收标准是**「仓库能公开、控制桥安全、没有本机路径」**，与「代码结构更好」是两组不同的证据，各自需要各自的测试。
- 6 条里只有第 6 条的 helper 侧属于**修洞**（必须做、已经在做），其余 5 条都是**换结构**（可以慢慢来）。
- 顺序不能反：P0 立契约、P1 消灭延迟解析之后，上面每一条才有干净的落点；先动结构再补契约，等于同时改行为和结构。
